# Verification and release commands

- `verify.sh` runs the root and package suites, including Cleanup in release mode to exercise optimized safety predicates.
- `dev-run.sh` builds Poptart into an ad-hoc-signed `.app` bundle pinned to `labs.playground.Poptart` and launches it, so permission grants survive rebuilds.
- `PoptartVerifier/main.swift` is a Foundation-only executable source intended to be the root package's `PoptartVerifier` target.
- `test_tooling.py` exercises deterministic corpus/evaluation behavior and fail-closed benchmark prerequisites.
- `benchmark_release.py` accepts only a real executable runner, exact local model, macOS 15+, and a physical Apple Silicon Mac whose chip and memory are recorded.
- `release/verify_release_inputs.py` validates real artifact hashes and measured reports before release.
- `release/sign_model_pack.sh` emits the base64 JSON envelope decoded by `SignedModelPackManifest` and refuses example or incomplete manifests.
- `release/notarize_app.sh` verifies Developer ID signing, submits with an existing Keychain profile, staples, and validates.
- `release/build_app.sh` assembles and signs an optimized arm64 app in a new output directory.

No script contains credentials, downloads a model implicitly, or turns absent evidence into success.

## Developer ID application

```sh
security find-identity -v -p codesigning
export POPTART_TEAM_ID='<Playground Labs Apple Developer Team ID>'
export POPTART_MODEL_PACK_PUBLIC_KEY='<base64 Ed25519 public key for the release channel>'
export POPTART_APP_UPDATE_FEED_URL='<HTTPS Sparkle appcast URL>'
export POPTART_APP_UPDATE_PUBLIC_KEY='<base64 Ed25519 public key generated by Sparkle>'
zsh Scripts/release/build_app.sh '<Developer ID Application certificate SHA-1>' .build/Poptart-release.app
sh Scripts/release/notarize_app.sh .build/Poptart-release.app '<existing notary Keychain profile>'
```

The build requires an installed, valid Developer ID Application identity and refuses an existing
output. It uses the source Info.plist version, includes LICENSE/NOTICE, dependency resource
bundles and pinned dependencies' license/notice files (including vendored code), and enables
hardened runtime with only Audio Input access. No debug hooks are compiled
in release. Signing contacts Apple's timestamp server; notarization uploads the app to Apple.
Before submission, `verify_app_signature.py` enforces the bundle identifier, Apple Developer ID
certificate and expected publisher Team ID, hardened runtime, secure timestamp, and exact approved entitlements.
An ad-hoc build cannot pass. Actual Developer ID signing/notarization and live microphone testing
under hardened runtime remain required; passing local policy tests does not establish those results.
See Apple's [notarization requirements](https://developer.apple.com/documentation/security/resolving-common-notarization-issues)
and [Audio Input entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input).

The Settings update action uses pinned Sparkle 2.10.0. The updater is created on that action;
background/informational checks are rejected by its delegate even if saved Sparkle preferences
request them. Automatic installation, profiling and remote release notes are disabled. Signed
feeds are required without a timeout exception, and update archives must verify before extraction.
The bundle embeds Sparkle's framework and installer helpers, removes unused XPC services, and
signs from the inside out. Development bundles report updates unavailable unless both appcast
environment values above are provided. Developer ID bundles require both values.

Keep the app-update private key in Keychain using Sparkle's `generate_keys`; the Model Pack key is
separate. After notarization, archive only the stapled app with `ditto -c -k --keepParent`, then use
Sparkle's `generate_appcast` in `.build/artifacts/sparkle/Sparkle/bin/` to sign the archive and feed.
Publish the generated signed feed and artifacts at the configured HTTPS destination. A real
update from an older notarized app remains a release requirement, including relaunch and storage
preservation. See [Sparkle's distribution guide](https://sparkle-project.org/documentation/).

## Benchmark runner

`zsh Scripts/privacy/check_fluid_logging.sh` compiles the pinned SDK logger in debug and
release configurations and checks that disabling it suppresses console output. Recognition
disables SDK logging before constructing inference components because SDK diagnostics contain
private vocabulary and transcript details. The guard also precedes Unified Logging; the script
tests console output, not the system log store. Logging must be disabled before any private work
starts; this API does not retract previously queued messages.

```sh
swift build -c release --product PoptartBenchmark
RUNNER="$(swift build -c release --show-bin-path)/PoptartBenchmark"
"$RUNNER" --fixtures Evals/fixtures/gold.jsonl --model /path/to/pack \
  --audio /path/to/audio --jsonl
python3 Scripts/benchmark_release.py --runner "$RUNNER" --model /path/to/pack \
  --audio /path/to/audio --output .build/hardware-report.json
```

The unpacked pack needs `manifest.json` with a positive, measured `cleanupTokenCeiling`,
`recognition/unified/` with the pinned FluidAudio assets, and `cleanup/` with Qwen weights,
configuration, and tokenizer files. Optional `recognition/ctc/` enables vocabulary boosting.
The runner does not download anything, invent a ceiling, or validate a pack's release signature.
Use the exact verified release pack when collecting release evidence.

Provide one `<fixture-id>.wav` per JSONL fixture: nonempty mono audio, finite samples, shorter
than five minutes. Audio is decoded only by this development executable. Use synthetic/public
fixtures; JSONL output includes the recognized transcript, delivered text, and fallback reason
(null when unavailable). These fields separate recognition errors from Cleanup errors. IDs must
contain only ASCII letters, digits,
hyphens, and underscores. All audio inputs are checked before any result is emitted.

The runner warms both models once, replays audio at device pace, and measures the existing
coordinator's release-to-delivery timing with its production deadlines. Delivery is a controlled
in-memory destination: these timings **exclude live Accessibility and clipboard insertion**.
They are pipeline evidence, not a replacement for the compatibility harness or manual delivery
checks. Model failures and fallback outcomes remain visible; incomplete timings fail the run.

`footprintBytes` is the post-Dictation physical footprint; the report's steady-state value is the
maximum of those snapshots. `peakFootprintBytes` is the kernel's process-lifetime physical
footprint high-water mark, including model loading and fixture decoding. `mlxActiveBytes` is
MLX's active allocation count, not a substitute for physical footprint. No memory threshold is
invented. Both models must remain loaded at every sample.

The runner writes and decrypts history through the production stores with a per-run in-memory
key, and round-trips settings. Its default temporary directory is deleted on exit. An explicit
`--history-directory` must be empty; records remain encrypted there after exit, but the
throwaway key is not retained. Never point this option at a person's Poptart data.

For the release baseline, reboot the declared physical Apple Silicon Mac, run macOS 15 or newer, close other
applications, and run the optimized command above without a prior inference run. Models load
before timed Dictations. Preserve the report, exact pack, fixtures, OS version, and operator notes.
The bundled gold corpus is a tooling smoke set; a representative release corpus and real model
artifacts are still required before claiming product-level p99. The Python gate rejects virtualized
or non-Apple-Silicon hardware, incomplete fixture coverage, invalid numbers, and absent residency/readback evidence.
Release input verification recomputes the summary from rows and matches latency, token ceiling,
and both memory measurements to production metadata; those fields stay null until measured.
Pass the same `--fixtures PATH` to the benchmark and release verifier when using a larger corpus.

## Privacy evidence

```sh
# Works without a pack; expected exit 3, dictationProven=false.
zsh Scripts/privacy/network_deny.sh --startup-only
# Requires real audio and the complete local pack; expected exit 0 only after successful Cleanup.
zsh Scripts/privacy/network_deny.sh --model /path/to/pack --audio /path/to/audio
# Optional --fixtures PATH selects the corpus matching those audio files.
# Interactive clean-install capture; authorize native packet capture first.
sudo -v
zsh Scripts/privacy/traffic_capture.sh
```

The deny script verifies IPv4/IPv6 connection attempts fail with kernel `EPERM`, launches the
ad-hoc DEBUG app in isolated storage, then runs the benchmark under the same sandbox. A full
pass requires every fixture to produce cleaned text plus encrypted-history and settings readback.
Fallback-only runs cannot pass. Logs and JSONL remain in `.build`; temporary app data is removed.
Local system IPC remains permitted. The sandbox constrains the launched processes, not unrelated
system services; it is not a shipping app entitlement or a claim about every possible code path.

The traffic script needs an interactive terminal, administrator capture privileges, a hosted
signed manifest, and `POPTART_MODEL_PACK_PUBLIC_KEY` configured for `dev-run.sh`. It starts native
`tcpdump` PKTAP capture on all interfaces before app launch, filters Poptart/effective-process
metadata, then checks the exact launched PID offline. Mark the download window **before requesting
the manifest**, and close it after installation and its network transfers finish. The script
observes another 20 seconds and retains the PCAPNG, packet listing, capture statistics, installation
receipt, and phase timestamps beside the output report. Capture errors, process-attribution
mismatches, packet loss, missing phases, and absent downloads fail instead of counting as silence.
Browser source-code links are outside this process capture; do not exercise them. This download
capture covers Model Pack installation; testing application updates requires a separate explicitly
marked capture with the configured signed appcast and an older notarized application.
The result covers this ad-hoc build and this observed session, not notarized-release certification.
Its `passed` field covers packet timing and process attribution only; the report explicitly sets
`destinationsVerified: false`. Traffic inside the marked window is not automatically proven to
belong to the manifest/artifact requests. Reconcile the retained packet destinations with the
signed manifest and its download redirects before treating this as complete privacy evidence.

Both scripts rebuild the development bundle and quit a running development Poptart first. Neither
modifies the normal support directory. An interrupted/failed run leaves `passed: false` rather than
a stale passing report. Full model execution, hosted download capture, and physical baseline measurements
remain pending until their external prerequisites exist.


## Release quality evidence

The release-input verifier requires a schema-3 report for the frozen, independently reviewed
Cleanup holdout and its complete prediction file. It recomputes the quality scores and enforces
all thresholds; matching a report hash alone is insufficient. See
[Evals/README.md](../Evals/README.md#frozen-release-holdout) for the review record and scoring policy.

```sh
python3 Scripts/release/verify_release_inputs.py \
  --artifacts /path/to/release-artifacts \
  --quality-report /path/to/release-quality/report.json \
  --quality-predictions /path/to/release-quality/predictions.jsonl \
  --quality-runner /path/to/retained/PoptartCleanupEval \
  --initial-release \
  --benchmark-runner /path/to/retained/PoptartBenchmark \
  --audio /path/to/measured-audio \
  --benchmark-report /path/to/hardware-report.json
```

Production metadata must also identify the actual report hash, artifact hashes/sizes, and measured
hardware results. These remain unset until collected; fixture integrity and development scores cannot
substitute for release evidence. Each prediction must record positive integer `inputTokens` within its
`maximumInputTokens`, and that maximum must equal the corresponding release configuration's
measured `cleanupTokenCeiling`. Current and predecessor evidence use their own release ceilings.
Release manifests also require the Qwen 2B base's four-bit affine configuration and matching
packed weight/scales/biases structure. Separate higher-precision LoRA adapters remain supported.
Both CTC model bundles and their vocabulary/tokenizer JSON must be present for recognition's
Personal Vocabulary support. Development manifests may omit these release capabilities.

Keep `native-resources.txt` beside each `--quality-predictions` file, including predecessor
evaluations. Release validation recomputes Cleanup timing and memory fields from those predictions
and the raw native resource report; missing evidence or altered measurements fail validation.


`--initial-release` explicitly attests that no pack has shipped. For updates, replace it with
`--previous-quality-report PATH --previous-quality-predictions PATH --previous-release-config PATH
--previous-artifacts DIR`. Re-evaluate the actual shipped pack with the current trusted runner,
source checkout, scorer, and frozen suite. The retained shipped release configuration binds the
previous model directory's inventory size/hash; its files must match the previous evaluation. Every quality dimension
must equal or exceed the predecessor's pass count on the same denominator. The verifier retains
predecessor report, configuration, and Cleanup inventory hashes in its output.

The `recognition/` and `cleanup/` directories contain the exact individual files served to the
installer. The verifier compares Cleanup file hashes to quality evidence and both directories,
the plain `manifest.json`, fixtures/audio, benchmark binary and source/pins to the M1 report.
The benchmark snapshots these identities before and after execution. Retain the measured binary,
exact audio, pack manifest, model files and matching source checkout; stale evidence fails.
These are evidence consistency checks, not authentication of arbitrary operator-supplied reports
or proof that an untrusted configuration was historically shipped.


Current quality reports must also include the native rejection probes automatically collected by
`Evals/baseline.py`. The verifier checks every frozen probe ID, error, fallback text, and duration.
Model predictions alone cannot satisfy this boundary-evidence requirement. Current release scoring
uses `release-v2`; v1 reports and reports without native probes are historical evidence only.


## Continuous verification

`zsh Scripts/verify.sh` runs the model-free build, root and six package suites, tooling tests,
frozen-fixture integrity, corpus reproducibility, repository verifier, and shell syntax checks.
`Training/prepare_corpus.py --check` fails on stale generated splits before tests can regenerate
those files. It also works on an uncommitted worktree without comparing intentional changes to HEAD.

`.github/workflows/verify.yml` runs that command for pushes, pull requests and manual dispatch on
Apple Silicon macOS 15 with Xcode 26.2 and the Metal compiler component. Checkout is commit-pinned,
read-only, and does not persist credentials. The workflow needs no signing secrets and performs
no model download, notarization, publication, or release-performance claim. Hosted execution must
be verified after the workflow is pushed; local verification alone does not establish that result.


## Per-file Model Pack publication

The installer places signed files directly at their runtime paths. It does not extract archives.
Prepare a directory with `recognition/unified/`, optional `recognition/ctc/` and root-level `vad/`, and `cleanup/`.
Generate its complete candidate manifest (the short checked-in example is only illustrative):

```sh
python3 Scripts/release/build_model_manifest.py --pack /path/to/candidate-pack \
  --base-url https://your-host.example/packs/0.1.0 \
  --version 0.1.0 --minimum-application-version 0.1.0 --maximum-application-version 0.1.0 \
  --cleanup-token-ceiling "$CANDIDATE_CEILING"
```

The command refuses an existing `manifest.json`, hashes all regular model files, rejects symlinks,
and prints each role's inventory size/hash for release metadata. The proposed ceiling is not
performance evidence: measure that exact candidate on the declared physical Apple Silicon baseline before promotion. The
inventory SHA-256 hashes the UTF-8 JSON map of pack-relative filenames to `byteSize` and `sha256`,
with sorted keys, compact separators, and ASCII escaping (`sha256-canonical-file-inventory-v1`).
The individual manifest entries carry each file's own size/hash, which installation and startup
verify against the actual loaded files. There are no compressed containers or extraction steps.

Run quality and declared-hardware gates against these exact files and manifest, then populate measured release
metadata and run the release verifier. Only after it passes, sign `candidate-pack/manifest.json`
with `sign_model_pack.sh`, retain the unsigned body alongside its envelope, and publish the
unchanged `recognition/`, `cleanup/`, and optional `vad/` files under the chosen HTTPS base URL. The hosted app
manifest URL points to the signed envelope. No files or credentials are uploaded by these tools.
